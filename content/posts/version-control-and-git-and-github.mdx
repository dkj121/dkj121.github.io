简单点说，不同于一般思路的直接每次仅仅储存修改过的每个文件，Git 仅负责维护一组文件各自的快照，而对于 未做修改的文件，则直接保留一个链接指向之前存储的文件。

### 2、Git 工作流

通常来讲，使用 Git 完成绝大多任务，只需要几个命令（对于一些不打算上传到远程的私密文件，可以在 `.gitignore` 文件中标注，**这很重要**）

> 这里是一组常用的 \.gitignore 模版文件集合 https://github.com/github/gitignore

|                      意义                      |               命令               |
| :--------------------------------------------: | :------------------------------: |
|                   初始化仓库                   |             git init             |
|                 追踪 filename                  |       git add \<filename\>       |
|                    提交更改                    | git commit -m '对本次更改的描述' |
|       从 remote 拉取（即同步远程到本地）       |       git fetch \<remote\>       |
|              新建 branchname 分支              |    git branch \<branchname\>     |
| 推送 branch 分支到 remote （即同步本地到远程） |  git push \<remote\> \<branch\>  |
|        选择目标 hash 节点 / branch 分支        |   git checkout \<hash/branch\>   |
|           将 branch 分支合并到主分支           |       git merge \<branch\>       |

而对于撤销操作这里没有做提及，主要是因为没有必要。撤销操作一定程度上不仅仅会破坏开发者的思路，同时也容易让开发者再次踏入之前撤销掉的操作。不如保留历史，当做错题集吧（
